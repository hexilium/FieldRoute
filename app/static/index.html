      SLA в пределах ресурсов

      Расширенный поиск сначала сохраняет базовый результат (до 30 000 проверок), затем использует оставшийся бюджет для составных перестроек. Для большого плана задайте, например, 60 000 проверок: это общий лимит, не 30 000 плюс 60 000. При том же полном бюджете базовый поиск всё ещё может оказаться лучше.

      Без целевого процента ищем максимум SLA в заданных пределах. С целевым процентом сначала достигаем его, затем сокращаем число инженеров и пробег. Число своевременных визитов и сумма опозданий не ухудшаются относительно исходного плана. Все ранее назначенные заявки сохраняются; для неназначенных места здесь не ищем.

      Это предпросмотр. Новый вариант применяется только кнопкой выбора. Лимиты действуют только для этого запуска, не для последующих событий и обычного пересчёта.

          Дополнительные требования
          Правила пересчёта

          Начатая работа сохраняется за инженером. Завершённые визиты учитываются по расписанию. Положение в пути оценивается по последнему достигнутому адресу.

          Первые два режима сначала учитывают выбранный приоритет назначения: «Сначала срочные заявки» уже допускает меньше обычных назначений ради срочных. При равенстве этих критериев: после основной цели — ускоряем срочные при тех же главных показателях цели; перед основной целью — допускаем дополнительных инженеров, километры и нарушения мягкого SLA. Раньше ценой обычных заявок — назначение и раннее начало срочных важнее общего числа назначений, даже если выше выбрано «Выполнить больше заявок». Обязательные закрепления, начатые работы, строгие окна и смены сохраняются.

          Разбор заявки

            Назначить вручную

            Выбранный исполнитель будет закреплён за заявкой. Можно изменить прежнее закрепление или закрепить текущего исполнителя. Проверка покажет допустимое расписание и его последствия до применения.

            Инженеры с учётом текущих закреплений

            Принадлежность к районам

            Задайте один district_id для каждого инженера и активной заявки. Значения должны совпадать в точности, включая регистр. Например, tverskoy. Адреса и координаты сами по себе район не задают. Пустые значения null в строгом режиме не допускаются.

            Раздел reference содержит подписи для удобства и не меняет адреса или заявки. Изменение районов доступно до событий. Никакие старые назначения не снимаются автоматически.
