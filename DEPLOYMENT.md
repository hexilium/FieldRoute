# Развёртывание для жюри на Ubuntu 24.04

На сервере должен быть checkout репозитория с файлами развёртывания.
Скрипт запускает именно эту копию: он не делает `git pull`, не выбирает ветку
и не публикует локальные изменения с твоего компьютера.

DNS-запись A домена должна указывать на IPv4 сервера. Если есть AAAA,
она тоже должна указывать на этот сервер с рабочим IPv6. В панели хостинга
разреши входящие TCP 80 и 443. Эти порты должны быть свободны: скрипт
не останавливает существующие Nginx, Apache, Caddy или другие сайты.

```bash
git clone URL_РЕПОЗИТОРИЯ fieldroute_result
cd fieldroute_result
sudo bash deploy-ubuntu.sh demo.example.org
```

Если репозиторий уже скопирован на сервер, достаточно последних двух команд.
Docker устанавливается из официального apt-репозитория, если его ещё нет.
Уже установленный Docker не заменяется; требуется Compose >= 2.24.4.
При конфликтующих пакетах установка останавливается, не удаляя их автоматически.
Скрипт включает автозапуск Docker и добавляет разрешения TCP 80/443, если UFW
уже включён; настройки SSH не меняет. Системный firewall не включается заново.

При первом запуске скачиваются данные Москвы и собираются дорожные графы.
На это нужны свободное место, память и время. Подбери размер сервера после
пробного запуска на реальных данных; скрипт не гарантирует работу на малом VPS.

По завершении выводятся URL, логин `jury` и случайный пароль из 48 hex-символов
(192 бита случайности). Передай их жюри приватно. Пароль хранится только
в закрытых файлах `.local/deploy/password` и `.local/deploy/credentials.txt`;
каталог имеет права 700, файлы — 600. Контейнер Caddy получает bcrypt-хеш.
Каталог `.local/` исключён из Git. Администратор сервера и владелец Docker
по-прежнему имеют доступ к конфигурации и секретам. Не запускай скрипт с
трассировкой и не публикуй вывод терминала с паролем.

```bash
sudo cat .local/deploy/credentials.txt
```

Скрипт проверяет доверенный HTTPS-сертификат, ответ 401 от API без пароля
и ответ 200 с паролем. Если сертификат ещё не выдан, он завершится с ошибкой,
сохранит данные входа и оставит контейнеры для диагностики. Исправь DNS/порты
и повтори запуск. Дополнительно проверь сайт с внешнего устройства.

## Обновление и управление

После обновления checkout повтори ту же команду запуска: пароль сохранится,
приложение пересоберётся, подготовленные дорожные данные будут использованы
повторно. Возможен перерыв в доступности во время обновления.

Команды ниже выполняются из корня репозитория:

```bash
sudo docker compose -p fieldroute-production --env-file .local/deploy/production.env -f compose.production.yml ps
sudo docker compose -p fieldroute-production --env-file .local/deploy/production.env -f compose.production.yml logs --tail 100 -f caddy api
sudo docker compose -p fieldroute-production --env-file .local/deploy/production.env -f compose.production.yml down
```

`down` останавливает сервис; данные карты и тома сертификатов сохраняются.
Не используй обычный `docker compose up` для управления этой установкой:
он запускает отдельную конфигурацию разработки.

## Границы защиты

В production наружу опубликованы только 80/443 Caddy; у API и дорожных
сервисов нет опубликованных портов. Пароль требуется для сайта, API,
потоковых расчётов и документации. HTTP перенаправляется на HTTPS.
Это не отключает другие контейнеры и сервисы, уже запущенные на сервере.

Постоянные сервисы перезапускаются после сбоя/перезагрузки и имеют ротацию
логов. Docker restart policy перезапускает завершившийся процесс, но не
лечит зависание процесса или состояние unhealthy автоматически. Приложение
читает карту в режиме read-only, число процессов поиска ограничено одним.

Эта конфигурация ограничивает доступ паролем, но не добавляет очередь расчётов,
rate limiting, жёсткие лимиты CPU/RAM или защиту от DDoS. Пользователь,
который знает пароль, всё ещё может перегрузить приложение. Подготовь
демонстрацию заранее и сохрани резервный результат для показа.

Основание настройки: [установка Docker на Ubuntu](https://docs.docker.com/engine/install/ubuntu/),
[Caddy basic_auth](https://caddyserver.com/docs/caddyfile/directives/basic_auth).
